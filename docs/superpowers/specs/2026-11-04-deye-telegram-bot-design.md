# Deye Home — Telegram-бот для гибридного инвертора Deye

Дата: 2026-11-04 · Статус: черновик на утверждение

## 1. Зачем

В Киеве регулярно отключают свет. Дом работает от гибридного инвертора Deye с батареями. Владелец хочет, где бы он ни был:

- сразу узнавать, что **свет пропал / вернулся**, и сколько длилось отключение;
- в любой момент посмотреть **заряд батарей, потребление, есть ли сеть**, на сколько хватит батарей и когда они зарядятся;
- видеть **статистику**: сколько часов в день был свет и сколько не было.

То же самое должны получать члены семьи (жена и т.д.), которых владелец добавит.

Приложение Deye Cloud уже есть, но оно не даёт нормальных уведомлений об отключении сети, статистики «часы со светом / без» и общего доступа для семьи в удобном виде.

## 2. Цели

1. Telegram-бот, работающий 24/7 на Synology NAS в Docker; ноутбук после установки не нужен.
2. Уведомления (со звуком): свет пропал, свет вернулся (+ длительность и прогноз до полной зарядки), низкий заряд во время отключения.
3. Тихие уведомления: батареи заряжены до 100%, нет данных от Deye / данные снова идут.
4. «Панель» — одно сообщение с кнопками, которые перерисовывают его же (без засорения чата).
5. Статистика по кнопке: день / неделя / месяц, листание назад до 90 дней.
6. Несколько пользователей; доступ выдаёт администратор (владелец) кнопкой.
7. Хранение истории и замеров — не более 90 дней, авточистка.

## 3. Не цели

- Управление инвертором, изменение любых его настроек. Бот **только читает**.
- Локальное подключение к инвертору/логгеру (Modbus, Solarman V5, RS485) — в этой версии не делаем (см. §5.2). Архитектура не должна мешать добавить локальный источник данных позже.
- Веб-интерфейс, графики-картинки, мобильное приложение.
- Работа в групповых чатах Telegram — только личные чаты с ботом *(решение Claude)*.
- Автоматические ежедневные сводки — статистика только по кнопке (явное требование: «чтобы не спамить»).

## 4. Анти-цели (провал, даже если «работает»)

- **Ложное «свет пропал»**, когда на самом деле молчит облако/логгер/интернет. Отсутствие данных ≠ отключение.
- Дребезг: серия «пропал/вернулся/пропал» из-за одного кривого замера.
- Спам: лишние сообщения, новые сообщения на каждую кнопку, автосводки.
- Посторонний человек, нашедший бота, видит хоть какие-то данные дома.
- Секреты (ключи Deye, пароль, токен бота) попадают в git, логи или чат.

## 5. Ограничения и факты

### 5.1 Оборудование (проверено по скриншотам и сети 2026-11-04)

| Что | Значение |
|---|---|
| Инвертор | Deye SUN-10K-SG05LP3-EU-SM2 (3 фазы, LV-гибрид), SN `2400000001` |
| Батареи | 2 × Deye SE-F12-C, номинально ≈ 24 кВт·ч суммарно (точную ёмкость взять из API/настроек, если доступна; иначе — из конфига) |
| Станция в Deye Cloud | «Home Deye», часовой пояс UTC+02:00 (Europe/Kyiv) |
| Логгер | Wi-Fi/BLE, SN `D00000000001`, прошивка `DYDA_WiBLE_1.6.2`, чип MXCHIP, IP 192.168.1.20 (DHCP), облако `logger-eu`, сеть `Home_IoT` |
| NAS | Synology DS725+, 192.168.1.10, SSH `ssh -p 22 admin@192.168.1.10` (ключ настроен). `sudo docker …` пользователь запускает сам; файлы Claude пишет без sudo |
| Роутер | ASUS ZenWiFi BQ16, 192.168.1.1 |

### 5.2 Источник данных — только Deye Cloud OpenAPI

Порт 8899 (Solarman V5) и 502 (Modbus TCP) на логгере **закрыты** (проверено сканом TCP 1–20000: открыт только 80 — веб-страница логгера). Это новый облачный логгер Deye, не классический Solarman. Поэтому единственный программный путь — **Deye Cloud OpenAPI**.

Что известно (из сторонних клиентов, **официальную документацию нужно сверить** на developer.deyecloud.com):

- Базовый URL для Европы: `https://eu1-developer.deyecloud.com/v1.0`.
- Нужны **AppID + AppSecret** (приложение разработчика) и **email + пароль** аккаунта Deye; токен: `POST /v1.0/account/token?appId=…` с `appSecret`, `email`, `password` = SHA-256 (hex, lowercase) от пароля. Токен имеет срок жизни — нужно обновление.
- В приложении Deye Cloud пользователь видит пункт «создать облачный ключ» — **неизвестно**, совпадает ли он с AppID/AppSecret. Разобраться на этапе реализации (первая задача плана).
- Станция зарегистрирована **на собственный аккаунт пользователя** (не установщика).
- **Запасной путь (решение пользователя):** если официальный OpenAPI получить не удаётся (ключ не подходит, регистрацию отклонили, нужных полей нет) — использовать неофициальный API, через который работает приложение/веб Deye Cloud, с теми же учётными данными аккаунта. Поэтому источник данных делается за интерфейсом-адаптером («официальный» / «неофициальный», в будущем — локальный), выбор адаптера — настройкой в `.env`. Риск неофициального API (Deye может его изменить) принят; при поломке бот должен явно сообщать «нет данных от Deye», а не ложные отключения.
- Данные в облаке обновляются примерно раз в **3–5 минут** → уведомления приходят с такой задержкой. Это принято пользователем.

Нужные показатели: SOC батареи (%), мощность батареи (знак: заряд/разряд), напряжение сети по фазам и/или статус сети, мощность сети, потребление (UPS-Load и Load), мощность PV, **время замера** (timestamp данных, не время опроса).

### 5.3 Технические решения

- TypeScript на Node.js, Docker (docker compose) на NAS в `/volume1/docker/deye-bot` *(решение Claude, по аналогии с имеющимся стеком Lampac)*.
- Исходники на Mac: `~/projects/deye-bot`.
- Хранилище: SQLite-файл в смонтированной папке (переживает перезапуск контейнера).
- npm-зависимости ставить с точными версиями (`--save-exact`).
- Секреты — в `.env` на NAS, `.env` в `.gitignore`, в репозитории только `.env.example`. Пользователь вносит секреты сам; в чат их не присылает.
- Язык интерфейса бота — русский. Часовой пояс — Europe/Kyiv.
- Git: Claude не делает коммиты; только предлагает текст сообщения.
- Тесты: минимальные, на чистые функции (детектор отключений, статистика, прогнозы) *(решение Claude; объём — на усмотрение исполнителя, без разрастания)*.

## 6. Поведение

### 6.1 Опрос и определение отключения

- Опрос облака раз в ~60 с *(значение по умолчанию, настраивается)*; при ошибках — экспоненциальная пауза, уважать лимиты API.
- Новым считается замер только с **новым timestamp данных**. Повтор того же замера — не новая информация.
- **Сеть отсутствует** — когда инвертор сообщает, что сеть недоступна (напряжение на фазах ниже порога / статус сети «нет»). Конкретный признак выбрать по реальным полям API. Не использовать «мощность сети = 0 Вт» как признак.
- **Пропала хотя бы одна фаза = «свет пропал»**: трёхфазный Deye при выходе любой фазы за пределы отключается от сети и переводит дом на батареи, т.е. для дома это отключение. Если пропали не все фазы — в уведомлении и на панели указать, какие (напр. «нет L2») *(решение Claude)*.
- **Антидребезг** *(решение Claude, ради скорости)*: если в данных есть явный признак/напряжения однозначны (все пропавшие фазы ≈ 0 В, остальные в норме) — событие по **первому** новому замеру; если значения пограничные/противоречивые — ждать подтверждения вторым замером. Цель: «свет пропал» приходит через 3–5 мин, а не 6–10.
- Время события = время данных первого замера в новом состоянии.
- **Нет данных**: если новых замеров нет > 15 мин *(порог настраивается)* — тихое «⚠️ Нет данных от Deye N мин» (один раз); когда данные вернулись — тихое «данные снова поступают». Если за время тишины состояние сети изменилось — отправить обычное уведомление о событии, пометив, что точное время неизвестно (интервал «между X и Y»).
- Состояние (текущий статус сети, начало текущего отключения, какие пороги уже отправлены) хранится в БД, чтобы перезапуск контейнера не порождал ложных/повторных уведомлений.

### 6.2 Уведомления (всем одобренным пользователям)

Формат — как в макетах `docs/superpowers/mockups/design-v1.html` и `charge-eta.html`. Первая строка — суть (её видно в пуше на экране блокировки).

| Событие | Звук | Содержимое |
|---|---|---|
| 🔴 Свет пропал · ЧЧ:ММ | да | дом на батареях; заряд %, потребление, «хватит ≈ N ч» |
| 🟢 Свет вернулся · ЧЧ:ММ | да | сколько не было (интервал), заряд %, мощность заряда, «⏳ до 100% ≈ N ч M мин (к ~ЧЧ:ММ)» |
| 🪫 Батарея 50 / 30 / 20 / 10% | да | только во время отключения, каждый порог один раз за отключение; сколько уже нет света, на сколько хватит |
| 🔋 Батареи заряжены · 100% | тихо | один раз за цикл зарядки; сколько заряжались *(предложено Claude, пользователь не возражал)* |
| ⚠️ Нет данных от Deye | тихо | см. 6.1 |

Прогнозы:
- **Хватит на** ≈ (SOC − резерв)% × ёмкость / текущее потребление. Резерв по умолчанию 10% *(решение Claude, настраивается)*.
- **До 100%** ≈ (100 − SOC)% × ёмкость / текущая мощность заряда. Показывать, только если мощность заряда заметная (> ~100 Вт), иначе «заряд не идёт». Всегда со знаком «≈»: около 90–100% заряд замедляется.
- Если в момент «свет вернулся» заряд ещё не начался — прогноз можно не показывать в этом сообщении (он будет на панели).

Пользователь может отключить у себя звук уведомлений в `/settings` *(предложено Claude; если окажется лишним — выкинуть)*.

### 6.3 Панель и кнопки

- `/start` (для одобренного пользователя) → «Панель». Все кнопки **редактируют то же сообщение**, новые сообщения не отправляются.
- Кнопки: 🏠 Панель · 🔋 Батарея · ⚡ Нагрузка · 📊 Статистика · 🔄 Обновить.
- **Панель**: строка статуса (🟢 Свет есть / 🔴 Света нет — дом на батареях, с какого времени), моноширинный блок: шкала заряда `▰▰▰▰▰▰▰▱▱▱ 72%`, мощность заряда/разряда, «хватит ≈» или «до 100% ≈», потребление, солнце, сеть (есть/нет, напряжение); внизу «обновлено N мин назад» (по времени данных).
- **Батарея** и **Нагрузка** — детальные вкладки; набор полей — на усмотрение исполнителя исходя из того, что отдаёт API (напр. напряжение/температура батарей, потребление по фазам).
- «🔄 Обновить» — перерисовать по последним данным (при необходимости — внеочередной запрос к API с учётом лимитов).
- Если данных давно нет — панель прямо говорит об этом, а не показывает старые цифры как текущие.

### 6.4 Статистика (только по кнопке)

Формат — `docs/superpowers/mockups/design-v1.html` (экраны 3–4), неделя — **текстовой таблицей** (выбор пользователя, вариант A в `stats.html`).

- **День**: часы со светом / без (и %), число отключений, полоска на 24 часа из 🟩/🟥 (по часу на клетку; клетка красная, если в этот час большая часть времени без света), список отключений с интервалами и длительностью, минимальный заряд, сколько кВт·ч взято из батарей. Кнопки: ‹ пред. день · День · след. день › · Неделя · Месяц · 🏠 Панель.
- **Неделя**: таблица по дням (свет, нет, число отключений), итог, % времени со светом, самое долгое отключение, сравнение с прошлой неделей; листание ‹ ›.
- **Месяц**: то же, но строки по неделям + итог.
- Отключения, переходящие через полночь, делятся между днями. Текущий день/неделя/месяц считаются «по сей момент».
- Периоды **календарные** *(решение Claude; даты в макете условные)*: неделя Пн–Вс, месяц — календарный. Сравнение «с прошлой неделей» — за тот же отрезок дней прошлой недели.
- Листание назад ограничено 90 днями; период на границе показывается частично с пометкой «данные с ДД.ММ».
- **Время без данных** (облако молчало, бот был выключен) показывается третьей категорией «❔ нет данных», в полоске дня — ⬜. Не приписывать его ни «свету», ни «без света» *(решение Claude — честность важнее ровных 24 ч)*.
- **Догрузка истории** *(решение Claude)*: если Deye OpenAPI отдаёт исторические данные — при первом запуске подтянуть до 90 дней назад, а после простоя бота — заполнить пропуск. Если не отдаёт — статистика копится с момента запуска.

### 6.5 Пользователи и доступ

- Администратор — владелец; его Telegram ID задаётся в `.env` при установке.
- Неизвестный пользователь жмёт Start → ему: «доступ по приглашению»; администратору: «👤 Имя (@username) хочет доступ к Deye Home» с кнопками ✅ Разрешить / ❌ Отклонить. Никаких данных до одобрения.
- Одобренные пользователи получают всё: панель, статистику, все уведомления.
- `/users` (только админ): список пользователей, кнопка «Удалить» у каждого.
- Если пользователь заблокировал бота — не падать, пометить и пропускать.

### 6.6 Хранение

- Храним: замеры Deye (≈ раз в минуту), историю отключений (начало, конец, длительность, заряд в начале/конце), пользователей, состояние бота.
- Раз в сутки удалять всё старше **90 дней** (кроме пользователей и текущего состояния).
- Логи приложения — в stdout; ротация логов Docker ограничена по размеру (напр. `max-size`/`max-file`).

## 7. Развёртывание

- Claude готовит `Dockerfile`, `compose.yaml`, `.env.example`, копирует файлы на NAS по SSH в `/volume1/docker/deye-bot`.
- Пользователь сам заполняет `.env` (AppID, AppSecret, email/пароль Deye, токен Telegram-бота от @BotFather, свой Telegram ID) и сам запускает `sudo docker compose up -d`.
- Контейнер с `restart: unless-stopped`.
- Проверка при установке: NAS, роутер и ONT провайдера запитаны от резервного выхода инвертора (иначе в отключение уведомления не уйдут). Это ответственность пользователя; бот не может это проверить.

## 8. Оставлено исполнителю

- Библиотека Telegram (grammY/telegraf и т.п.), ORM/драйвер SQLite, структура проекта, схема БД.
- Точные эндпоинты и поля Deye OpenAPI (по официальной документации) и признак «сети нет».
- Детальный состав вкладок «Батарея» и «Нагрузка».
- Тексты сообщений в рамках макетов.
- Объём тестов (минимальный, на чистую логику).

## 9. Решения, принятые Claude (на проверку пользователю)

- Только личные чаты; групповые не поддерживаем.
- Опрос раз в 60 с, порог «нет данных» 15 мин, резерв батареи 10% для прогноза.
- Антидребезг: событие по первому замеру при однозначных данных, второй замер — только при пограничных значениях.
- Пропажа любой фазы = «свет пропал», с указанием, каких фаз нет.
- Календарные неделя (Пн–Вс) и месяц; время без данных — отдельная категория «❔ нет данных».
- Догрузка истории из Deye при первом запуске и после простоя (если API это позволяет).
- Тихое уведомление «заряжено 100%».
- Персональное отключение звука в `/settings`.
- Docker на NAS в `/volume1/docker/deye-bot`, TypeScript/Node, SQLite.
